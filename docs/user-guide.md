# Terminal Pilot — macOS Terminal 管理器 MVP

原生 macOS App，管理 **macOS 內建 Terminal.app** 的獨立視窗。
沒有內嵌 terminal，不依賴其他 terminal app。原生介面使用 SwiftUI/AppKit + AppleScript；Web Push 加密使用 Python `cryptography`。

## 開啟

```bash
cd terminal-pilot
open 'dist/Terminal Pilot.app'
```

第一次啟動，macOS 會詢問是否允許 **Terminal Pilot 控制 Terminal**，請按允許。
如果曾拒絕，到「系統設定 → 隱私權與安全性 → 自動化」開啟，再按 App 的「重新連接」。
不需要輔助使用或螢幕錄製；網頁的 Terminal 文字快照也透過同一項自動化授權取得。

Mac 的 Codex「選擇舊對話」預設以所選專案資料夾篩選；只有勾選
「包含其他資料夾的對話」才傳入 `--all`。啟動手機核准通道時，遠端 Codex
介面同時收到明確的 `--cd <專案資料夾>`，不只切換啟動程序的工作目錄。
「續接此專案最近對話」也使用同一個資料夾。參數依據：
[Codex CLI reference](https://learn.chatgpt.com/docs/cli/reference)。

## 本地工作網頁（v0.8）

在 Terminal Pilot 右下角按 **「網頁」→「在這台 Mac 開啟網頁」**。
預設網址為 `http://127.0.0.1:8765`；埠被占用時會自動換一個，請以 App 顯示的位址為準。
不用上線、不用 tmux。Terminal Pilot 必須保持執行；關閉管理器視窗仍可用，⌘Q 才停止網頁服務。

- 工作清單與原生 App 同步，包含 Codex、Claude Code 與一般 Terminal；需要你的工作排前面，並標明 agent 類型。
  一般 Terminal 可查看文字快照，尚不提供任意 shell 輸入。
- 手機可按 **「＋ 新工作」**，填工作名稱、選 Terminal／Codex／Claude，再選電腦上的資料夾。
  可直接輸入完整路徑（支援 `~/`），或按「選擇資料夾」逐層瀏覽並使用目前位置。
  按「開啟工作」會在 Mac 建立獨立 Terminal 視窗；建立成功後自動連到對應工作。
  新工作自動保存到手機與 Mac 共用的「專案紀錄」，可在建立時固定。
- 手機 **「專案紀錄」** 可重新開啟曾保存的工作，名稱、資料夾、類型與固定狀態沿用 Mac 設定。
  Codex／Claude 每次開啟都能選「建立新對話、續接此專案最近對話、續接指定對話」。
  指定對話填 session ID／名稱；若 Mac 原設定為互動式對話選單，手機會要求改選上述方式。
  成功後保存這次選擇；連點或同一請求的網路重試不會重複開窗。若連線中斷而結果不明，先查看工作列表。
  新 agent 的首次登入、信任與權限選單仍需在電腦完成。
- 聊天介面顯示近期的使用者訊息與 AI 回覆，支援多行輸入、基本 Markdown 與程式碼。
  Enter 換行，按送出或 ⌘／Ctrl + Enter 送出；手機直接用一般文字輸入框。
  手機版採整頁捲動，工作列表、對話與 Terminal 文字快照會隨內容延長，輸入框在對話下方。
  往上閱讀時不會被新訊息拉回底部；返回列表、重進同一對話會保留捲動位置。
  對話頂端的「工作列表」按鈕會保持可見，也可用瀏覽器上一頁返回、下一頁重進對話。
  首次進入、從手機通知開啟或按「最新」時，排版完成後定位到最新訊息的開頭，長回覆不會跳到末尾。
  工作視窗、Brain 主對話與各件事情的討論使用同一套定位；手機會避開固定標題列。
  一般返回對話仍保留閱讀位置；同一則回覆持續變長、或正在讀較早內容時，背景更新不會捲動頁面。
- 回覆送進原本 Terminal 分頁的 Codex／Claude Code，不會叫回或還原其他視窗。送出前檢查原視窗、TTY、
  Terminal 程序與該 agent 的前景程序；已離開 agent、視窗已關閉或目標已改變時拒絕送出。
- 「已送到 Terminal」代表文字已送達；Agent 實際接收後才會出現在聊天紀錄。
  網路中斷不會自動重送，草稿保留；先看 Terminal 快照確認，避免自己重複送出。
- 主動點進工作對話，載入成功後會清除點選當下的提醒，與電腦雙擊叫回一致，手機與電腦同步。
  瀏覽器前進重進對話也適用；只開列表、重新整理、背景更新或停留在對話裡不會清掉新通知。
  載入失敗、載入完成前離開或切到背景不會標已讀。載入期間出現的新通知仍保留。
  啟用 lifecycle hooks 的工作，送出後也會由 agent 事件清除；可隨時按「已處理」確認當下通知。
- 對話依正式 hook 的 Codex thread ID／transcript path、精確 turn ID 或 Claude session ID 對應，不以資料夾猜測。
  Claude 舊工作可由 CLI 的 PID 登錄檔核對 PID、資料夾和啟動時間後讀取，無法確認時不以專案猜測。
  背景子工作的完成通知不會蓋掉已由 hook 確認的主對話。無法精準對應的舊工作可按「查看 Terminal 內容」，
  下次主對話回報後再對應；不必為了管理器更新中斷既有工作。

手機使用：打開 **「允許區網／Tailscale 裝置連線」**，在手機瀏覽器開啟 App 顯示的電腦 IP 位址，
輸入六位數配對碼。配對碼 10 分鐘有效；「重設配對」會撤銷全部舊連線及通知訂閱。
同一 Wi-Fi 使用區網 IP；跨網路可用雙方已加入的 Tailscale IP。不需要公開部署或安裝手機 App。
HTTP 區網限可信網路使用，跨網路用 Tailscale 的加密連線，不要設定路由器公開轉送。
一般重啟會保留配對，並恢復原先已開啟的網頁服務。HTTPS 網頁會在此裝置儲存配對，讓主畫面 App 重開可直接連線；「登出」也會關閉此裝置推播。

### Brain 個人助理與工作管理（v0.12）

網頁頂端保留 **個人助理／工作管理** 兩種模式。個人助理有主對話，以及各件事情獨立延續的討論；
工作管理仍有原本的視窗列表、專案紀錄、原始 session 對話、語音、核准和關閉 Terminal。原生 Mac 視窗管理不變。

- 主對話用來交代新事情與跨工作統整；Brain 可把一句話拆成數件事。按「接著聊哪件事」或訊息下的事情連結，繼續該件事的討論，也可手動建立事情。
- 事情不等於 Terminal：同一件事可有多個執行 session。各自保存目標、訊息、草稿、閱讀位置、交辦與未讀；另一件事完成只提示，不插入全文或自動切換。
- 輸入框上方顯示目前討論範圍。主對話已讀不會清掉其他事情的未讀；通知可直接進入所屬事情。助理歷史可分頁讀取更早訊息。
- 交辦紀錄的「讀取原始內容」在助理內展開保存回報與近期 session 對話；手機整頁閱讀、桌面並排，可引用回報接著問，不把全文複製到輸入框。原 session 讀取器仍限制至多最近 150 則，並非全歷史匯出。
- 一個專用 Brain Codex 依序統籌，事情紀錄獨立保存；不為每件事建立新的 Brain Terminal，也不宣稱模型上下文完全隔離。執行 session 可同時工作。

- 在 Brain 輸入「請讓網站工作查明登入問題，再請 API 工作核對介面」等交代。
  Brain 讀取目前開啟的 Codex／Claude 工作與近期對話，選擇合適的精確 session、排隊派送，
  收到正式完成回覆後彙整；需要時會在原目標內繼續交辦另一個工作。狀態與時間放在輸入框上方。
- 也可只問「現在有哪些事需要我？」；這類整理不會自動派工作。首次使用前不會主動呼叫模型。
  無法判定目標時會提問。這版派送範圍是**已開啟的 agent**；尚未開啟的專案請從工作管理建立／續接。
- 首頁不再顯示逐個 Terminal 卡片。交辦紀錄收在可展開的區塊，可查看原工作或按「自己接手」。
  手機沿用整頁捲動；新訊息不會把正在閱讀舊內容的人拉到最下方，按「最新」可跳到最新訊息開頭。
- Codex 原始核准／問題表單直接出現在 Brain 對話裡，保留理由、範圍與選項，由你決定。
  Brain 不自行核准，也不以普通文字模擬允許。Claude 首次開專案的資料夾信任確認也可在手機處理；其他 Claude 權限／未接通的舊工作仍需電腦處理。
- 「暫停交辦」停止後續派送，已執行的 agent 繼續；收到的結果仍可整理。
  「自己接手」、工作管理送出回覆，或偵測到原對話的新使用者訊息，都會停止該工作的自動續派。
  對 Brain 說某件事先不要做，可撤回該件排隊／後續交辦；不會終止已開始的程序。
- 切換畫面保留兩邊各自草稿，不取消已交辦的事。原視窗重新綁定、關閉或對話改變時不猜測新目標。
  忙碌時等原回合結束才送出，每次交代最多 6 次自動派送，不讓 agent 無限互相交辦。
- Brain 對話、請求識別碼與派送紀錄存於 Application Support 的私有 `brain.sqlite3`。
  重啟後以完整交辦文字核對原對話；結果不明時不自動重送。相同訊息的網路重試沿用相同識別碼。
- Brain 委派工作的通知會由整合結果接手；原工作在 Mac／管理畫面的未讀仍保留。
  其他手動工作的通知流程沿用原設定。Brain 推播只含狀態，點擊進 Brain；進度不推播。
- Brain 現在使用真正的 **Codex session**，在獨立的「Brain · 個人助理」Terminal 執行，工作位置為 `~/brain`。
  沿用本機 Codex 的模型、登入、工具與權限，不再呼叫獨立的 `gpt-4.1-mini` 規劃模型。
- 手機按「開啟／續接 Brain Codex」只開視窗，不送模型訊息；第一次交代也會自動開啟。
  連接後按「查看 Brain 對話」可看原始輸入、進度與回覆；Mac 也可從工作管理叫回這個 Terminal。
  交辦紀錄可展開看實際指令與 agent 回報。手機主對話仍顯示整理後的自然語言。
- 重啟 Pilot 會沿用同一段 Codex thread。關閉 Brain 視窗後重新開啟，只續接記錄的確切對話，
  不用「最近對話」猜測；不影響原本其他 Brain 或專案 session。
- 手機交代與原工作結果透過 Codex 的正式 `turn/start` 接入同一對話，保有 Codex 歷史、工具與核准。
  送出前持久保存識別；斷線時只確認原回合，不盲目重送可能已執行的工作。
- 舊版訊息與交辦紀錄保留。若 agent 已完成但後續規劃失敗，仍顯示 agent 原始結果並標示尚未整合。
  收結果回合不能撤回交辦；已有進行中交辦的工作不能又被重派。

語音仍可在工作管理使用；這一版的統一 Brain 對話先提供文字交代，沒有背景語音或耳機控制。
協調介面與恢復規則見 [Brain API 契約](brain-api.md)。

### Claude 首次開啟資料夾（v0.10.1）

Claude 啟動時的「信任資料夾」會顯示為手機確認卡，列出完整路徑與原始提示，
由你選「同意並信任此資料夾」或「不同意並離開」。這同時適用工作管理與 Brain 的確認區。
此提示出現於 Claude hooks 啟動前，因此由 Mac 核對目前 Terminal 畫面與原 Claude 程序；
只處理已辨識的資料夾確認，不將一般回覆當成核准，也不更改 Claude 的信任設定檔。
送出紀錄會跨 Pilot 重啟保留，重複點擊或失去回應不會再次輸入。其他 Claude 工具權限、
登入與初始化選單仍需在電腦操作。介面契約見 [Claude 資料夾信任確認](claude-workspace-trust.md)。

### 手機新增專案資料夾（v0.10.2）

在「工作管理 → ＋ 新工作 → 選擇資料夾」找到要放專案的位置，按「新增資料夾」，
輸入名稱後選「建立並使用」。建立成功會自動填入專案路徑，工作名稱未填時也會帶入；
接著選 Codex、Claude Code 或一般 Terminal，即可開啟新專案。建立資料夾本身不會啟動 agent。
同名檔案、資料夾或連結會提示衝突，不覆蓋或自動產生副本。斷線時可重試同一筆請求；
仍未確認時重新讀取資料夾清單後選用。介面契約見 [手機專案資料夾](mobile-directories.md)。

### iPhone 主畫面 App 與通知

1. Mac 已連上 Tailscale 後，在 Pilot「網頁」開啟 **「iPhone 通知（Tailscale HTTPS）」**。
   使用專屬的 `https://<這台 Mac 的名稱>.ts.net:8443` 私人網址，不使用 Funnel，也不需要開放整個區網。
   Pilot 會設定此埠的 Tailscale Serve，既有其他埠服務不變；8443 若屬於別的服務則拒絕覆寫。
   若 Tailscale 要求啟用 HTTPS，依 App 顯示的管理連結完成一次設定。
2. iPhone 開啟 Tailscale，用 Safari 開啟 HTTPS 網址，選 **分享 → 加入主畫面**。
3. 從主畫面的 Terminal Pilot 圖示開啟，輸入 Mac 顯示的六位數配對碼。
   配對碼過期時按 Mac 的「更新配對碼」；不會撤銷既有連線或通知。
4. 展開工作列表的 **「iPhone 通知」→「開啟通知」→「允許」**。
5. 按「測試通知」後鎖定手機；Mac 會在 5 秒後送出，無需保持網頁前景。
   「已交給 Apple 推播服務」只代表服務接受，是否到達、聲音與震動仍需在真機確認。

通知限 iOS 16.4 以上的主畫面 Web App，亦可用支援 Web Push 的 Mac Safari 測試。
聲音與震動依 iPhone「設定 → 通知 → Terminal Pilot」及「聲音與觸覺回饋」、專注模式決定。
通知只含工作名稱與狀態，不傳送對話、終端快照、資料夾或配對憑證；使用 Web Push 端對端加密，經 Apple 推播服務傳送。
Mac／Pilot 需保持運作並能連上 Apple，iPhone 收推播需要網路；開對話則還需要 Tailscale 連線。

- 背景監看只推播主工作完成、真正等你回覆／核准或錯誤；進度訊息、工具執行、自動安全審查與背景子工作不推播。
  權限事件會比對該輪 Codex 記錄中的實際審查模式；無法確認需要人工核准時，不以該權限事件觸發手機通知。
  Claude 的權限通知確認真正顯示人工提示後才推播；不重複推播完成後的 idle_prompt。
  狀態持續約 8 秒仍需要你才推播，期間恢復工作或已讀就取消。同一裝置同一筆不重複推播；開啟通知時不補送既有舊提醒。
- 送出前再次核對未讀與通知 ID，已讀或 agent 已恢復工作時取消；暫時失敗會退避重試，過期訂閱自動移除。
- 圖示徽章是待處理 **待處理工作數**，不是訊息數。點通知直接進對話，沿用載入成功才標已讀的規則。
- Mac 與手機共用每筆工作提醒的已讀紀錄，包含 Codex 啟動選單與 Claude 資料夾確認。在任一邊查看／標示已處理，另一邊於下次同步清除；啟動確認被讀過不代表已核准。
- 手機已讀後立即核對角標；延遲推播、重新連線或返回前景也會重新同步，即使待處理清單沒有改變。新提醒與不同 Brain 議題的結果仍保留。
- iOS 要求每筆背景推播顯示通知，不發送只清徽章的靜默推播；電腦先處理完時，背景手機的舊徽章可能保留到下一次開啟或新通知。
- 一般重啟保留通知金鑰與訂閱；關閉手機通知或 Mac「重設配對」可撤銷。私鑰與訂閱存在 Pilot Application Support，檔案權限 0600。
- Service Worker 不快取對話或憑證。網頁、API 和訂閱操作都有來源、配對檢查；只接受 Apple 的 HTTPS 推播端點且不追蹤轉址。

目前支援 **Codex 與 Claude Code 文字回覆**。新開的 Codex 工作也支援 **手機直接核准**：
確認卡片顯示原要求的理由、指令、檔案變更或選項，按允許／拒絕／取消後回傳該筆正式要求。
不預先勾選允許、不修改 Codex 權限政策、不用 Terminal 按鍵模擬核准。
收到 Codex 的解除等待事件才標為已處理；電腦先回答、重複點擊或連線中斷時不會重送舊決定。
Claude 的權限選單、macOS 系統權限、首次設定與任意 shell 輸入目前仍需在電腦操作。

舊版開啟的 Codex 工作請在輸入框上方按 **「接通手機核准」**，閱讀說明後按 **「停止並續接，啟用手機核准」**。
這會停止該工作的目前執行，確認程序結束後，在新 Terminal 視窗接續同一個 thread 與 Codex home，保留對話紀錄。
不會自動中斷其他工作；未完成的執行不會因續接而自動重跑。新開的工作不需要這一步。

每個新 Codex 工作有自己的本機 `app-server --listen unix://…`，原本的 Terminal TUI 以 `--remote` 連接；
不使用 tmux。手機透過 Unix socket 上的 WebSocket 加入已載入的同一個 thread，接收原核准要求及執行事件。
後端由 Terminal 的啟動程序持有，重開 Pilot 不會停止 Codex。沒有開公開連接埠，也不修改全域 Codex 設定。
首次啟動／更新提示仍需在電腦完成；尚未建立對話時會顯示連接提示。
舊 daemon 工作仍只讀狀態；獨立 `--no-daemon` 工作需經上述續接才支援手機核准。

輸入框正上方以簡短一行顯示處理狀態與經過時間；按「最新」可跳到最新訊息開頭。
進度文字留在對話裡，狀態區不覆蓋畫面上方。
計時優先使用 Codex 本輪正式 `task_started` 時間，中途補充訊息不重設；缺少正式時間時才標示「距離送出」。
舊 session 也能從確切對話紀錄的生命週期事件顯示「本輪進行中」，但這不代表舊 session 已接通核准。
Codex 的 commentary 標成「處理進度」，不當成完成結果播放。斷線會明確標示。
進入對話清除提醒紅點，等待提示持續到要求已處理；期間停用普通文字／語音送出與舊摘要播放。
同一筆要求的重播不重複通知，新要求仍會產生新提醒；恢復工作後清除。
網頁在前景時約每 2.5 秒更新，啟用通知後另由 Mac 背景監看新提醒。
對話顯示目前主對話記錄尾端最多 8 MiB 中的最近 150 則訊息；不包含隱藏推理、系統指令或完整工具紀錄。

### 手機關閉 Terminal

進入工作後按 **「關閉 Terminal」**，確認畫面會列出同視窗的全部工作與狀態。
按 **「停止工作並關閉」** 才會停止這個視窗的程序並關閉視窗；其他視窗、專案紀錄與已保存對話保留。
確認後新增／更換分頁會拒絕關閉，避免影響未確認的工作。未儲存的編輯內容可能遺失；不使用強制 SIGKILL。
斷線或關閉結果未知時不自動重送，先查看列表與電腦狀態。

連線恢復並成功取得對話後，先前的載入錯誤會清除；送出結果未知的警告仍保留。
斷線時保留草稿，輸入框旁顯示無法送出的原因與「立即重連」，不會自動重送文字。

### 前景語音測試

更新後先在 Mac 結束並重開 Terminal Pilot，再重新整理 iPhone 的 HTTPS 網頁／主畫面 App。
進入 Codex 或 Claude Code 對話，展開回覆框上方的 **「語音回覆」**；對話上方也有同名捷徑。

1. 按 **「開始錄音」**，允許麥克風，說完按 **「說完送出」**。自動轉錄並送到錄音時選定的工作，
   不需要加入回覆框或再按送出。每次最多 60 秒，時間到也會自動轉錄送出；按「取消錄音」可放棄。
2. Agent 回覆完成後，按一次 **「聆聽結果」**，自動整理約 2～3 句的口語摘要並播放。
   同一按鈕可暫停、繼續及重播，不必再分別按產生摘要和播放。摘要不改寫對話原文。
   準備時分別顯示「整理摘要」與「產生語音」；只有進度回報時顯示「尚無完成回覆」。
   支援 Audio Session API 的 Safari 會在你按下播放時使用 `playback` 模式，避免 Web Audio
   預設 ambient 模式被 iPhone 靜音鍵靜音；暫停、播完或離開時還原。系統中斷後可按「繼續聆聽」。
3. 「剛才說的內容」保留轉寫文字供查看；原有打字草稿不會被清掉或混入語音指令。
   若送出失敗或結果不確定，保留文字並提示查看對話／Terminal，不自動重試。
   只有這時才出現「保留到回覆框」，供確認後手動處理。
4. 「語音說明與試聽」中的 **「試聽範例」** 只朗讀固定測試句，不傳送對話。

這階段驗證前景的「錄音 → 送出 → 回覆 → 一鍵聆聽」。關閉面板、離開對話或切到背景時，
停止錄音／播放並作廢尚未送出的語音；已送到 Terminal 的回覆不能撤回。已開始的雲端請求
可能仍完成並計費，但晚到的轉寫不會送給其他工作。Agent 恢復或回覆改變後，舊摘要失效。
播放使用 Web Audio，在點擊時啟動音訊，之後才等待摘要與音訊；切背景後關閉音訊環境，
返回時由下次點擊重建。沒有靜音保活、自動播報新通知、鎖屏錄音或耳機選 session；
這些留給 Expo App 的真機里程碑，見 [VOICE.md](../VOICE.md)。

此功能**使用雲端 OpenAI API**：錄音結束時上傳該段錄音；按聆聽時上傳所選工作的最後一則
agent 回覆、對應使用者問題與工作狀態做摘要，再將摘要做語音合成。依 API 用量計費，
介面會標示 AI 合成語音。一般閱讀／打字不觸發這些服務，Terminal 快照不送入摘要。
Mac 透過 macOS 鑰匙圈讀取 `openai-platform-api` 金鑰；請在「環境設定」驗證並儲存自己的 API key。
既有同服務的金鑰會沿用，不需要私人腳本；金鑰不傳給手機或寫進專案。錄音與產生的音訊只在記憶體處理，不另存檔。
語音 API 可供日後 Expo App 共用；網頁的錄音／播放介面屆時更換成原生音訊。

## 使用方式

1. **自由視窗管理**：現有 Terminal 視窗／分頁自動出現。**雙擊項目**或按「叫回」，
   就會還原對應視窗、選中正確分頁並移到最前面；成功後將當下通知標為已讀。
   同一次雙擊只會叫回一個目標，即使第一下之後列表重新排序，也不會改叫回另一列。
   也可按「收起」，自由拖動視窗再收起／叫回，位置會由 Terminal 保留。勾選兩個視窗後按「並排」，
   「還原排列」會復原上一次操作前的位置、大小和縮小狀態。
   每列 `…` 可重新命名、放到左側或右側。排列使用管理器所在的螢幕，右邊保留管理器寬度。
   「新工作」預設為**一般 Terminal**：只切到選定資料夾、設定工作名稱，不啟動 AI。
2. **AI 完成紅點**：按「新工作」，選 Claude Code 或 Codex CLI，再選專案資料夾。
   AI 仍在新的 Terminal 獨立視窗運作。送出問題後收起視窗，這輪回覆結束就會有紅點。
   雙擊／「叫回」成功，或直接按「已處理」，會確認你點選的那筆通知；送出下一個問題／AI 恢復工作也會自動清除提醒。
   管理器頂部紅色數字、待處理篩選、選單列數字及 Dock badge
   都會更新。關掉／重開管理器後，仍開著的 Terminal 工作會保留未讀。
   數字代表未讀工作數，同一工作多次通知仍算一個。歸零時數字徽章消失；App logo 本身沒有紅點。
3. **待處理優先排序**：未讀的完成、等待確認與錯誤通知自動排在最前面，以通知時間由新到舊排列，
   關閉 Terminal 視窗／分頁後，下一次成功同步便從 Mac 與手機工作列表移除，未讀不會保留該列或計入徽章。
   清除提醒後回到一般排序，依最近 AI 狀態更新、開啟或叫回時間排列。
   一般 Terminal 初次被發現時記錄時間；重新整理不會改變時間，同時間使用固定順序，避免列表跳動。
4. **專案紀錄與固定專案**：從「新工作」開啟的工作會自動保存名稱、資料夾與啟動類型；
   可勾選「固定此專案」，也可在「專案紀錄」點大頭針。固定專案在前，各組最近開啟的在上。
   關閉 Terminal 或管理器後紀錄仍保留，按「開啟」會沿用相同資料夾、名稱與類型。
   同一紀錄重開不會重複新增；同資料夾可保留不同名稱或不同工具的工作設定。
   現有視窗可從 `… → 儲存為專案…` 加入；受管 AI 會預填資料夾，一般 Terminal 需手動選擇。
   專案可搜尋、改名、更換資料夾或移除紀錄；移除紀錄不會刪除資料夾或關閉 Terminal。
   Codex 與 Claude 專案每次按「開啟」都會先顯示選擇：建立新對話、選擇舊對話、
   續接此專案最近對話或續接指定對話。一般 Terminal 仍直接開啟。
   成功開啟後會保存這次選擇，供下次預選；取消或視窗啟動失敗不會修改設定或最近開啟時間。
   也可在專案 `… → 對話啟動方式…` 修改預選方式，當次開啟仍能更改。
   「最近」每次都依該資料夾重新判定；要一直接回同一段對話，請選「指定」並填 session ID 或名稱。
   「選擇舊對話」會在 Terminal 開啟 agent 自己的對話清單；Codex 可勾選包含其他資料夾的對話。
   續接仍透過通知 bridge 啟動，保留完成通知與活動狀態。舊版 Codex 專案設定會沿用。

按右下角 `?` 的「10 秒通知測試」可不呼叫 AI，測試縮小後亮紅點的流程。
測試工作會明確標成「通知測試（非 AI）」。關管理器視窗會留在選單列；⌘Q 才結束 App。
退出管理器不會終止 Terminal 或 AI。

### 紅點代表「現在需要你處理」

- 在 Terminal Pilot **雙擊工作列**或按**「叫回」**，成功切到對應分頁後，將點選當時的通知標為已讀。
- 直接按**「已處理」**，清除所選通知。
- 關閉 Terminal 視窗／分頁，該工作與其未讀數便從列表移除，不需要先標為已讀；專案紀錄與對話歷史仍保留。
- Claude／已接通活動狀態的 Codex 收到你送出的新問題時，上一筆通知已被新一輪取代；
  等待確認的提醒則在 AI 恢復執行時解除。只輸入草稿還不會清除。
- Codex 完成後延遲返回的背景工具不會清掉完成通知；其他工具的背景進度不會解除正在等待的確認。
  已被新一輪取代的舊回報也不會重新點亮紅點。

自行點 Terminal、⌘Tab、切換 Terminal 分頁、收起／排列視窗、刷新或重啟管理器，都不會標為已讀。
叫回失敗也不會清除。操作期間或視窗已在前景時收到的新通知仍為未讀；已讀只套用那筆通知，
不會將整個 session 永久忽略。新通知會更新同一列的紅點與時間，不增加重複工作列。

### Codex 自動清除

新開或透過「接通手機核准」續接的工作，使用正式 runtime 事件回報開始、等待、恢復與完成。
舊工作若已信任 Pilot hooks，仍沿用 hooks；未接通的工作可保留對話續接。
讀取通知不等於核准；不監聽鍵盤，也不因 Terminal 取得焦點就清除提醒。

## MVP 邊界

- 已開著的任意 Terminal 可以管理視窗。**已跑著的 AI session 不會被自動注入通知 hook**；
  請從「新工作」開受管 session，或用下方 bridge 指令啟動／續接。現有 AI 不會被中斷。
- Claude 使用 `--settings` 加入本次執行的生命週期 hooks，支援執行中、等待確認、完成及錯誤。
- Codex 每個新工作使用獨立 app-server 與原 TUI，透過正式 runtime 事件及本次執行的 `notify`／hooks
  回報狀態。附加 hooks 仍遵守 Codex 原本的信任機制；手機核准與基本 runtime 狀態不依賴信任 hooks。
  原使用者／專案 notify 會由 bridge 轉呼叫；特殊 profile 自訂 notify 尚未支援轉呼叫。
- 「完成」是本輪回覆結束，不代表實作、測試、部署或驗收都已成功。
- 一個 terminal 分頁對應一個主要 AI session；tmux、SSH 遠端 AI、自動接管背景作業不是本版範圍。
- 同視窗的多個分頁會分列，但「收起」和「排列」以整個視窗為單位。多個分頁勾選會去重成一個視窗。
- 原生全螢幕／不同 Space 的排列行為依 macOS 而異；請先在一般桌面視窗測試。此版不切換 Space。
- 這是本機 ad-hoc 簽署的 Apple Silicon 原型，尚未做 Developer ID 公證或安裝包。

## 從現有 Terminal 啟動／續接

在**已回到 shell prompt** 的 Terminal 執行，請替換專案路徑：

```bash
python3 scripts/bridge.py launch claude --cwd /path/to/project --label '登入問題'
python3 scripts/bridge.py launch codex --cwd /path/to/project --label '補測試'
python3 scripts/bridge.py launch codex --cwd /path/to/project -- resume
python3 scripts/bridge.py launch codex --cwd /path/to/project -- resume --last
python3 scripts/bridge.py launch claude --cwd /path/to/project -- --resume SESSION_ID
python3 scripts/bridge.py launch codex --cwd /path/to/project -- resume SESSION_ID
```

正常啟動不修改 `~/.claude/settings.json`、`~/.codex/config.toml` 或 shell 設定。
視窗管理只讀 Terminal 的標題、TTY、位置、分頁選取與縮小狀態。
網頁聊天功能唯讀 Codex／Claude Code 既有的本地對話紀錄；只有按「查看 Terminal 內容／更新」時，才讀取所選分頁的
可見文字及捲動紀錄（最多 60,000 字元），不讀取其他分頁。Terminal 快照不另存檔、不傳第三方服務。
一般對話讀取也只在本機處理；主動使用語音功能時的 OpenAI 資料流另見「前景語音測試」。
通知 bridge 只存 session、TTY、專案路徑、工作名稱、狀態、時間、事件 ID 與 Codex／Claude 對話識別／檔案位置，
不存 prompt／AI 回覆。網頁存取憑證保存在 Application Support 的 `web-auth.json`（0600），一般重啟沿用，重設配對時更換。
HTTP 瀏覽器使用 sessionStorage；HTTPS 主畫面 App 另使用 localStorage 保留配對，登出時清除。不將憑證寫入專案或存取日誌。
服務預設只綁 localhost；所有資料及操作需要配對憑證，檢查 Host／Origin，不開 CORS，不載入外部腳本。
本機狀態放在 `~/Library/Application Support/Terminal Pilot/`，`preferences.json` 保存未讀確認、
視窗別名、活動時間與專案紀錄。舊版設定會保留並補上新欄位；通知測試不加入專案紀錄。
bridge 用檔案鎖及原子寫入，App 沒開時仍可接收完成事件。
